# 两份版本对比与融合后的规格

版本：1.1，2026-09-14。本文以用户最新消息为准，替代此前“首页按地区”“固定温哥华 2 篇＋加拿大／美国／国际各 1 篇”的建议。

输入：用户的《New Text Document.txt》、此前对话方案，以及后续明确要求。参考文件里的“先手写一期”“绝不需要后端”等是待评估建议，不是新的执行授权或先决条件。

## 一、我的原方案遗漏或不适配的地方

| 项目 | 原方案的不足 | 融合处理 |
|---|---|---|
| 用户与选题 | 北美视角较宽，未明确本地补贴与公众参与机会 | 加拿大主视角；温哥华／大温特殊影响和本地机会主动寻找 |
| 首页 | 原有五类不符合新确定的主题 | 金融、科技、民生（含政策）、移民；地区作为文章信息 |
| 前端 | Astro 对两种阅读模板并非必要 | 采用 Python＋Jinja2 提前生成内容 |
| 引用核验 | 方向正确，但未把地方政策资格、辖区、征询阶段列为字段 | 添加辖区、状态、资格、金额、期限、官方行动入口 |
| 新闻归档 | 每日内容进 Git、长期保存音频，违反新要求 | 正文、证据与音频进私有 R2；按 5 天规则删除 |
| 公开音频 | 删除首页链接仍可能通过旧音频地址访问 | 正文和音频都经 Worker 检查期限 |
| 用户运营 | 原始范围没有召回、数据与退订 | 添加小型用户记录；具体功能留到任务三实现 |
| 成本 | 原估算没有用户功能增长与备份／过期访问限制 | 基础 5—10 美元；邮件或 Worker 升级单列 |

部分缺口源于新增需求，并非早期方案在当时范围内必须实现的功能。

## 二、你的版本值得采用的部分

- Python 流程、Jinja2 模板，内容与展示分离。
- 来源清单、提示词、模型名独立配置，方便自己维护。
- 先筛选摘要，再对入选事件获取证据，减少模型输入。
- 来源编号由程序分配，网址和机构信息由程序填写。
- 每一步保存可恢复状态；失败只重做缺失步骤。
- 音频不进 Git；正常输出供所有读者重复使用。
- 先完整手动试跑，再启用定时执行。

## 三、你的版本需要纠正的判断

| 原判断 | 修正 |
|---|---|
| RSS 天然合法、免费、没有上限 | 分发格式不自动授予再发布权；逐源核实允许的获取和使用方式，遵守限流 |
| 抓不到全文就用摘要写深度分析 | 摘要可用于发现线索；缺少资格、条件、数字的材料不能扩写成深度结论 |
| 引用编号存在就避免幻觉 | 真实来源也可能被错误引用；增加逐项证据对照与独立模型复核 |
| 模型最坏只能编不存在的编号 | 模型还可能误读日期、国家、币种、政策阶段、因果关系和否定词 |
| 加链接和 AI 声明就等于免责 | 不能替代版权、准确性、隐私和投诉处理责任 |
| 每天几次请求一定低于任何免费额度 | 以具体模型与项目面板为准；还要算复核、重试和单次 token 限额 |
| Azure F0 自动有付费 SLA | 免费额度不能直接等同付费可用性承诺；仍需故障处理 |
| 私有仓库 60 天无活动会停 schedule | 官方规则针对公开仓库；无论哪种都要独立漏跑监测 |
| 06:00 太平洋时间固定等于 14:00 UTC | 改用 America/Vancouver；BC 新规则为全年 UTC−7，不套用洛杉矶 |
| 访客任意增加成本都一样 | AI 不随阅读重复运行，但 Worker、数据库、音频读取和邮件仍有计量 |
| 没有用户系统就绝不能有后端 | 定向召回、退订、画像和过期访问控制确实需要小型托管接口 |

## 四、融合后的产品

### 首页与详情页

首页提供金融、科技、民生（含政策）、移民四个主题入口，以及最近五期日期。进入主题直接打开当期主题分析；不增加地区分类页。详情页按 Title、播放器、正文、Citations 排列。地区、政策状态和有效期限是内容标记，不形成第三种阅读模板。

首版产量默认：每主题每日最多一篇约 1,000 字的分析，包含 2—3 个相关事件；证据不足可少发。重大地方政策可在所属主题增加一篇专项解读，每日总量按最多 5 篇、约 6,000 字控制。此处是实施默认，替代之前按地区硬分配篇数的建议。

新闻筛选优先关注本地实际收益或可参与机会，再看加拿大整体影响。国际扫描必须执行，有重要事件就按完整分析标准写入主题，不因“国际”标签降低深度。没有入选时记录原因，不用别的日期凑数。

### 加拿大视角与温哥华专项

每个事件说明：事实、影响对象、影响过程、条件与不确定性、可采取的下一步。不是每条新闻都适用于所有加拿大人；明确受影响群体。

存在温哥华特殊影响时，独立写一至多个段落，解释本地差异及证据。区分温哥华市、列治文、本拿比、素里、大温区域和 BC；一个城市的政策不能自动套到其他城市。

地方补贴与公众咨询必须检查：发布机构、适用辖区、个人或组织资格、金额与币种、草案／已通过／生效／申请中／征询中／已截止、开放及截止日期、时区、官方申请或参与链接。找不到的字段写“官方材料未明确”，不能猜测。

例如温哥华 grants 目录包含面向非营利组织的项目，不能把它概括成“每位居民都能领补贴”。[官方目录](https://vancouver.ca/people-programs/grants-and-awards.aspx)

采集新增或实质更新的政策页面。第一次发现旧项目不等于昨日发布；仅导航、页脚或时间戳改变不算实质更新。旧材料只作明确标记的背景。

### 架构与阶段边界

Python＋Jinja2 在 GitHub Actions 生成内容；DeepSeek 写作、Gemini 独立复核；Google Cloud Text-to-Speech 配音；正文与 MP3 放 R2 私有存储；Cloudflare Worker 负责网页入口与期限控制。D1 为订阅和活动状态保留接口位置，不用于保存全文。

Google TTS 取代上一稿 Azure 默认：用户已有 Google 账号、没有 Azure，复用身份更省事。Google Cloud 项目、计费、TTS API 和凭证仍须单独开通，AI Studio Key 不可直接当作 Cloud TTS 凭证。

任务三保留轻量版 A 召回建议：获得同意后记录已知活跃，超过 72 小时提醒，同一不活跃周期最多两次；跨设备识别有限。任务四建议不做公开留言，用私下纠错表单。任务五严格按发布自然日保留五天；新闻删除不连带删除退订与同意记录。
