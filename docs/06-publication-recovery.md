# 自动更新补救机制（2026-11-09）

## 为什么改

11 月 7 日 #80 的 RSS 候选包含只有链接的摘要；模型加入无证据支持的具体金额、时间等细节，且部分稿件不足 800 字。重写依然使用相同材料，导致本地板块缺稿、整期发布失败。

## 现在的处理

1. 仍以温哥华时区前一天为新闻日期；收集最近七天的候选。
2. 从公开可访问的原文提取正文，让 DeepSeek 与 Gemini 使用同一份证据。不绕过登录、付费或访问限制。搜索摘要不视为正文。
3. 温哥华本地也可采用已启用的 BC 媒体直接来源，优先于搜索链接；民生板块继续排除 BC 和大温本地新闻。
4. 不合格时保留已通过板块，只修复缺失板块。缺正文先补抓；仍有证据问题或反复字数不合格，则排除该板块已失败的素材，选其他未发布候选。最多五轮，随后流程可完整重试一次。
5. 每板块 1–3 篇、800–1500 字、至少一篇钱包影响文章；所有发布文章必须有 Gemini 审核通过标记和 citations。审核服务不可用不等于审核通过。
6. 近七天已发布来源清单保存在 R2 的 `site/data/publication-history.json`，同时保留媒体原文 URL 与发现 URL。失败草稿不算“已使用”。首次升级从当前线上一期和可确认已发布的缓存历史开始建立清单。
7. 发布前再次检查全部板块、字数、引用、钱包标记和审核标记。文章、音频等先上传，首页入口最后上传。

## 自动补跑

GitHub Actions 每天 UTC 12:17、14:17、16:17、18:17、20:17、22:17 检查。每次先比较线上新闻日期与应发布日期；已经更新则不生成、不调用模型。全流程并发锁防止多次发布竞争。失败通知仍由 Healthchecks 发送。

GitHub 定时触发本身可能延迟或丢失，多时段检查提供冗余，不构成严格准点承诺。

## 查看结果

- GitHub → Actions → Daily News Pipeline：`freshness` 是日期检查，`generate` 包含生成、审核和发布。
- 每次运行的 `generated-site` 附件保存候选、拒绝原因及最终 sections。
- 网站 `/data/index.json` 的 `publication_date` 是新闻日期；`generated_at_local` 是网页生成时间；每篇的 `evidence_review_passed` 表示审核通过。
- 手动 Run workflow 日期可留空，自动取温哥华昨天；要发布需勾 publish。线上已经是该日期或更新日期时，运行跳过。

## 验证

本地 45 项 Python 测试、7 项 Worker 测试通过。覆盖正文证据传递、抓取失败回退、避免重复抓取、审核后保留钱包要求、已用来源窗口和过期补跑检查。真实生成及上线结果见对应 GitHub Actions 运行记录。

移民板块新增 IRCC 官方 Atom 和 CIC News 专业来源；严格筛选签证、居留、入籍等主题。手动强制重建可勾 force；日常自动检查不勾，避免重复调用。
